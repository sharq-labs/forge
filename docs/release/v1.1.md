# v1.1-benchmark — frozen release, fifth draw

**Read this paragraph before any number below it.** The generator behind these
2000 cases has now been corrected **five times**, and the fifth correction —
`5cd1b75`, *"ratings are sized at the operating point the run reaches, not the
asymptote"* — is the reason the false-reject rate improved from **1/241 (0.4 %)
at v1.0 to 0/241 (0.0 %) here.** No code changed to earn that. The one case that
moved is `S00709`, which v1.0's own README diagnosed as a mislabel and declined
to fix; the fifth draw fixed it, and the tool's answer was the same before and
after. **The improvement is the benchmark agreeing with the tool, not the tool
getting better.** Five corrections is now the headline fact about this
benchmark's history: every figure on this page is a figure the generator has
been adjusted against five times, which is exactly why 600 cases are sealed and
have never been scored. Reproducibility, by contrast, is the strongest evidence
here and is not affected by any of that — the same case-set digest and the same
four metrics have come out of **three independent environments**, including a
Docker container on an Azure kernel running **ngspice 39** where the other two
run 42.

### The digest refused a case set that had silently changed

The case-set digest was added at v1.0 so that "a run against different cases is
visibly a different run rather than a silently different number." It was tested
for real **one day later**, when `main` turned out to be carrying the fifth
draw:

```
$ python benchmarks/hard/score_hard.py --src src \
    --cases ../forge-main/benchmarks/hard/cases_hard --workers 4 --split dev

--split dev needs a split file matching these cases.
  cases           ../forge-main/benchmarks/hard/cases_hard
  digest          e14542c1e09f258d
  split file      ...\benchmarks\hard\split_hard.json (digest mismatch)
Regenerate with: python benchmarks/hard/split_hard.py --cases ../forge-main/benchmarks/hard/cases_hard
```

Without it, the fifth draw would have scored against v1.0's split and produced a
number that looked like a tool improvement. **1744 of 2000 case files had
changed and nothing else in the repository said so** — not the index, not the
composition line, not the README, all of which report the same 342 / 1658 / 144
for both draws. The mechanism is the only thing that noticed.

## Status — not yet landed, and why

This page describes a **local candidate**, not a pushed release. The tag is not
cut. `main`'s history is contested: another session merged `core-guards` into a
`main` that predates `label-corrections`, and that half-merge is still sitting
there unpushed. Landing order is the repository owner's call, not this round's.

The candidate is `origin/main` + `origin/core-guards` + the evidence and
presentation commits, with `NEEDS.md` and `benchmarks/hard/README.md` conflicts
resolved by keeping both rounds' sections.
