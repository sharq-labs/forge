## Hypothesis set (a DRAFT, registered before any CONFIRMATORY exposure)

These hypotheses were designed AFTER the Kirkaldy BIG 14 holdout had been observed. They are registered before
confirmatory exposure only, not before all exposure. Their prediction entries name a placeholder condition, so
the registry digest changes once the owner designates the confirmatory design.

| id | statement | note |
|---|---|---|
| `bat-h0-arrhenius-linear` | fade = k q exp(-Ea/R (1/T - 1/Tref)) -- the Kirkaldy probe law, kept as the reference competitor | the NOT MET reference: re-tested only as a competitor, never re-scored on its observed holdout |
| `bat-h1-two-mechanism` | fade = q [A1 exp(-B1 (1/T - 1/Tref)) + A2 exp(+B2 (1/T - 1/Tref))] -- SEI above, plating below | non-monotone temperature dependence (a minimum of the fade rate inside the window) |
| `bat-h2-power-law` | fade = B q^z exp(-Ea/R (1/T - 1/Tref)) | sub-linear throughput dependence (z selected by the pre-registered FidelityGraph screen) |
| `bat-h3-sqrt-plus-cold-plating` | fade = a q^0.5 exp(-Ea/R (1/T - 1/Tref)) + b q exp(-g T) | SEI (sqrt) plus plating that grows exponentially as T falls |

Each is a canonical `Hypothesis` (kind EQUATION, PROPOSED) whose parameters stay UNKNOWN until they are fitted on
exploratory data. Its structure digest comes from the fade-family canonicalizer `forge.battery.fade_family/1`,
which abstracts every constant, including exponents and additive offsets inside `exp`. For the novelty check,
`q^0.5` and `q^0.8` are therefore the same family, and so are `exp(-b/T)` and `exp(-b(1/T - 1/Tref))`. The
snapshot entries also carry their expressions and declare a numeric-equivalence method.

## What the pre-registration fixes (`real_preregistration()`)

- **Sections.** All 21 required sections are present.
- **Confirmatory dataset.** It is named by **identity fields only** (an allowlist, string values). A content-like
  key in any section is refused, case-folded. This is a LEXICAL guard: it cannot read meaning.
- **Kirkaldy archives.** Both are listed as **EXPLORATORY ONLY** and its NOT MET stays (pinned by digest).
- **Falsification rule.** It is MACHINE-READABLE: `prediction_deviation`, k = 3,
  `resolution = min(0.25 |p|, max(1.2 k sqrt(u_pred^2 + u_obs^2), 0.004))`.
  - A falsifier is sealed only where `k sqrt(u_pred^2 + u_obs^2) <= resolution`.
  - Every condition that fails the rule is declared UNTESTABLE, with the rule's inputs, before exposure.
    `verify_discipline` recomputes the rule for each declaration and checks each sealed falsifier's criterion and k.
  - The rule has a stated blind spot: with u_obs = 0.0015, a prediction below about 0.018 cannot be tested.

## Dry run (SYNTHETIC battery-like data, TEST-profile ledger; never the confirmatory holdout)

The dry run walks the full chain:

1. Hypothesis → DurableCampaign ExposureAuthority, plus a DatasetManifest with salted row commitments and design
   conditions.
2. ExposureGate (the data authority's rows go to the gate only) → sealed falsifiers, with recorded per-condition
   abstentions → multiplicity.
3. FidelityGraph screen with a false-elimination audit → owner approval → confirmatory release through the gate.
4. Adjudication → Red Team → issuer-bound credibility (test mode) → one Discovery Passport per hypothesis.

What the dry run shows about the design:

- **No discrimination.** The synthetic confirmatory points (drive cycle at 15 / 32 °C, 500 / 900 Ah) do not
  separate h0–h2: every sealed falsifier (the two 32 °C points) is NOT_REFUTED. The two 15 °C points predict too
  little fade for the rule (its blind spot) and are recorded as per-condition abstentions. A SURVIVING status from
  this design would say little. Before approval, the real design needs conditions where the competing predictions
  differ by more than the resolution, and a lower observation uncertainty or higher throughput at cold
  temperatures, where plating hypotheses differ most.
- **h3.** It is declared UNTESTABLE before exposure, with the rule inputs: its exploratory fit cannot reach the
  resolution.
- **Novelty.** Against the snapshot, every hypothesis is known_equivalent. Even a confirmatory success of
  these families would be a confirmation of known families, not a discovery, unless a systematic prior-art
  search says otherwise.
- **Red Team.** It FALSIFIES every hypothesis's threshold claim at the edge of the attack space, where model
  routes disagree. That is agreement of models, not a measurement, and it blocks the credibility requirement as
  it should.
- **No discovery.** No passport counts as one: the run is a dry run, credibility is in test mode
  (`requirement_met` is never true there), and the ledger is a TEST profile.
