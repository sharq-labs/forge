# Oracle register

Where each thing Forge tests itself against actually comes from, and whether it
could ever contradict Forge.

**The distinction this register exists to make.** A test whose expected value
was written by the same people who wrote the implementation, from the same
formula, is not independent validation. It is a consistency check, and a
consistency check cannot fail for the reason that matters — the formula being
wrong. Circular entries below are marked as such rather than counted.

An `INTERNAL_BENCHMARK` is never independent. Its cases were generated by code
in this repository, its truth was assigned by that code, and its generator has
been corrected in response to what scoring it revealed.

## What this register says when read as a whole

**Three genuinely independent oracles exist**: `O-UNITS`, `O-INCROPERA-5.1`,
`O-KITTEL-5`, plus `O-NGSPICE` which is real but off the benchmark path.

Two of the three are **citations, not executable checks**. They constrain a
constant at the point it is declared; nothing runs them, and nothing would go
red if the constant drifted away from the source.

**Everything that produces a number on the scored path is internal.** The
benchmark is circular by construction — the generator and the implementation
share this repository, and the generator has been corrected several times in
response to what scoring it revealed. The dev split's 1362/1400 is a number the
generator was tuned against.

**And the hold-out no longer supplies the exception.** It was carried as the
one untuned figure; it has been opened twice, and its recorded result describes
a case set edited four times since. `HOLDOUT_STATUS.md` is explicit that no
figure from it may be presented as blind, and that no reshuffle of these 2000
cases can restore that. **This repository currently has no untainted
end-to-end figure.**

**One level is attainable on the reference path**, `ANALYTICALLY_VERIFIED`, and
it is earned by two routes inside one repository agreeing about one governing
equation. That is worth having — it caught real defects — and it is not
physical validation. The check says so in its own detail string, which is the
right place for it to say so.

**No oracle anywhere establishes that a declared applicability bound is the
scientifically correct bound.** That is the largest single gap in this register,
and it is a capability gap rather than a defect: nothing in the current
architecture can carry the provenance of a threshold. See
`CORE_ASSURANCE_MATRIX.md` §C for which bounds are sourced and which are not.
